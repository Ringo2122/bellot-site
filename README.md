# МониТорг — агрегатор торгов

Сайт: https://ringo2122.github.io/bellot-site/
Админка: https://ringo2122.github.io/bellot-site/admin/

Каталог торгов по имуществу должников с восьми площадок: auction24.by (Госторги), e-auction.by (БелЮрОбеспечение),
ipmtorgi.by (ИПМ-Торги), beltorgi.by (Белреализация), konfiskat.by (ТД «Восточный», торги — на torgikonfiskat.by),
belauction.by (БелАукцион; по robots.txt — только первые страницы списков), minskestate.by (электронные торги МГЦН),
mgcn.by (очные аукционы МГЦН: строка таблицы в посте — карточка, итогов онлайн нет; `app/mgcn.rb`).
cpo.by (ЦПО) с 25.09.2026 не собираем: это рекламная витрина торгов ИПМ. Разделы: недвижимость, легковые авто, грузовые и автобусы,
спецтехника, оборудование (от 3 000 BYN), право аренды (МГЦН: помещения, открытые площадки, земля в аренду; расчёт аренды
по БАВ — `app/bav.rb`, зона Минска — `app/zones.rb`, сетка зон — `tools/zones.rb`).

## Как обновляется

GitHub Actions (`.github/workflows/update.yml`) запускается каждые 10 минут. `app/gate.rb` решает, что делать:

- настал час обхода (по умолчанию **11:00 и 18:00 по Минску**, часы задаются в админке) — полный цикл:
  1. `app/update.rb` — обходит площадки: новые лоты добавляет, у известных обновляет цену и срок,
     закрытые отправляет в архив (срок заявок истёк или лот снят с площадки), собирает итоги торгов.
     `app/backfill.rb` добирает из архивов площадок завершённые за 30 дней торги, которых у нас нет, —
     сразу в архив с итогами (не больше 350 лотов с площадки и 25 минут за прогон). Архив хранится год.
  2. `app/market.rb`, `app/market_realty.rb` — рыночный ориентир по Kufar для новых лотов.
  3. Память коммитится в `data/`;
- в админке нажали «Опубликовать» — только сборка;
- иначе — ничего.

Затем `app/build.rb` собирает сайт в `_site/` с решениями из админки и выкладывает на Pages,
а `app/sync.rb` кладёт в админку копию каталога и отчёт о запуске.

Ночью (23:30) — `.github/workflows/archive.yml`: архив площадок за год (`backfill.rb`, `YEAR_ARCH=1`, до 4,5 часа):
завершённые за 365 дней торги (konfiskat.by — за 3 месяца), кроме «Оборудования», belauction.by (robots.txt) и mgcn.by
(итогов нет); главное фото —
320 px, в галерее до 5 фото ссылками. Площадка, загруженная целиком, отмечается в `data/backfill_year.json` —
когда отмечены все, прогон ничего не делает.

Запустить вручную: Actions → «Обновление сайта» → Run workflow.
Правка кода в `app/` пересобирает сайт без обхода площадок.

## Админка

База — Supabase (`supabase/schema.sql`, применяется через Management API; повторный запуск безопасен).
Сайт остаётся статическим: база хранит решения человека, робот читает их при сборке.

| Таблица | Что |
|---|---|
| `overrides` | правки лота (поле, изменённое человеком, робот не перезаписывает), модерация, «Рекомендуем» |
| `lot_photos` | фото, загруженные в админке |
| `dup_rules` | склеить / не склеивать пару лотов |
| `settings` | площадки и разделы, минимальные цены, часы обхода, правила калькулятора, тексты, бот |
| `lots` | копия каталога с отметками сборки — для списков в админке |
| `runs`, `bot_runs` | отчёты робота сайта и Telegram-бота |
| `leads` | заявки с формы «Помощь в аукционе» |

Модерация: лот, появившийся после подключения админки (`settings.mod_since`), с замечаниями —
нет фото, цены, города, срок заявок по правилу, похож на лот другой площадки — не показывается,
пока его не одобрят. Любой лот можно скрыть или вернуть на проверку.

Доступ: вход по логину и паролю (`admin_login`) выдаёт ключ сессии на 30 дней, он идёт в заголовке
`x-admin-token`; все таблицы закрыты RLS. У робота и бота своя бессрочная сессия — секреты GitHub
`SB_URL`, `SB_KEY` (публичный ключ), `SB_TOKEN`. Посетителю доступны только функции из списка в конце
`supabase/schema.sql` (заявка, ошибки у посетителей, вход в кабинет); остальные вызываются только изнутри базы.

Если база не ответила, сборка останавливается и на сайте остаётся прежняя версия — иначе вернулись бы скрытые лоты.

## Безопасность

- Правки базы — в `supabase/*.sql`, применяются в Supabase → SQL Editor (или через Management API); `schema.sql` —
  полное описание, повторный запуск безопасен. Новая функция, которую должен вызывать посетитель, — в список прав в конце `schema.sql`.
- Сайт и админка: политика CSP (скрипты — свои и Leaflet с cdnjs с проверкой целостности SRI; запросы — только в Supabase),
  всё, что пришло с площадок и из форм, выводится через `esc()`; ссылки площадок на сайте — только http(s) (`build.rb`).
- Робот: внешние программы — только списком аргументов (без оболочки); `curl` — только http(s), с лимитом размера.
- GitHub Actions: сторонние модули закреплены по коммиту (`uses: …@<sha> # vN`), права на запись — только у шагов сборки.
  Обновлять версии — заменой коммита на новый того же или следующего тега.
- Секреты — только в секретах GitHub (`SB_TOKEN`, `ALERT_TG_TOKEN`, `TG_TOKEN`) и в хранилище Supabase (ключ GitHub для
  мгновенной публикации). В коде и в репозитории их нет.

## Память

| Путь | Что |
|---|---|
| `data/lots.json` | короткие записи всех лотов, строка на лот; `status`: `active` / `archive` |
| `data/det/<key>.json` | подробности лота |
| `data/ph/<key>.jpg` | фото, 400 px (архив площадок за год — 320 px) |
| `data/backfill_skip.json`, `data/backfill_year.json` | архив площадок: отброшенные лоты; площадки, чей год загружен |

`data/` пишет только робот. Руками не править — следующий прогон перезапишет. Править лоты — в админке.

## Локально

```bash
ruby app/update.rb && ruby app/build.rb    # сайт в _site/, без админки
MSG="что изменено" ruby tools/push.rb   # залить код в репозиторий (data/ не трогает)
```

Нужны ruby и curl; для фото — `sips` (macOS) или ImageMagick.
С переменными `SB_URL`, `SB_KEY`, `SB_TOKEN` сборка применяет решения из админки.
